# Замер судьи «утверждение следует из цитаты»

12 ноября 2026. Это замер перед решением. 15 ноября судья встроен: `sa.py judge`, субагент `.claude/agents/judge.md`, шаг в скилле `research`, предупреждения в `check`. Первая проверка на живом проекте в `docs/fixes.md`, прогон 11.

## Вывод

Haiku в роли судьи поймал все 25 намеренных искажений и ни одного не пропустил. Если судья видит окружение цитаты в сохранённой копии, он задевает 29 из 369 настоящих фактов, около 8%. Из этих 29 четыре оказались настоящими ошибками агента, которых `check` и `red-team` не заметили. Проверка 394 пар заняла 106 секунд и стоила 7 центов в ценах API. Встраивать стоит, но только как предупреждение и только для фактов из внешних текстовых источников. Дополнение от 15 ноября: на снимках и PDF судья поймал 21 искажение из 21 и не задел ни одного из 25 настоящих фактов, раздел ниже.

## Зачем

`check` сверяет, что цитата дословно есть в копии источника. Следует ли утверждение из цитаты, он не проверяет. У обычного чата нашлись именно такие ошибки: доля за квартал подана как доля за полугодие, опрос про подписки вообще подан как опрос про онлайн-кинотеатры (`docs/comparison.md`).

## Как мерили

- Настоящие факты: все 369 действующих фактов с цитатой из `kion-trial`, `salon-booking` и `radar-megafon`. Из них 276 из внешних источников и 93 из выводов расчётов.
- Искажённые: 25 пар, написаны вручную по образцу ошибок чата. Цитата настоящая, утверждение изменено: другой период, другой охват, другое число, другой предмет, намерение подано как сделанное, один отзыв подан как массовое явление, смысл перевёрнут. Список в `docs/judge/distorted.json`.
- Судья: Claude Haiku 5.5 через Claude Code без инструментов, в пустой папке, пакетами по 30 пар в случайном порядке. Какие пары искажены, он не знает. Ответ на пару: «да», «нет» или «частично» с причиной до 12 слов.
- Два варианта. В первом судья видит только утверждение и цитату. Во втором ещё и окружение цитаты: по 350 знаков копии источника с каждой стороны, для расчётов по 700.

Без окружения судья бесполезен: он задевает каждый четвёртый настоящий факт. Почти всегда причина одна: цитата короткая, а деталь из утверждения стоит в источнике рядом. Единственное искажение с ответом «частично» вместо «нет»: к верному утверждению добавлен срок «30 дней», которого в источнике нет.

Повторный прогон с окружением дал 27 срабатываний вместо 29. Ответы на границе «да» и «частично» немного плавают.

## Ограничения замера

- Искажения писал разработчик, а не жизнь. Настоящие искажения могут быть тоньше.
- Набор из трёх проектов одного агента. Судья и агент из одного семейства моделей.
- Разбор 29 срабатываний сделан одним человеком без второй проверки.
- Окружение берётся из нормализованного текста: нижний регистр, без кавычек.

## Что предлагаю

1. Встроить как субагента `judge` на Haiku после разбора источников. Вход: утверждение, цитата, окружение из копии. Только факты из внешних текстовых источников.
2. Ответ записывать в реестр. `check` даёт предупреждение, не ошибку: «нет» требует переписать утверждение или заменить цитату, «частично» требует расширить цитату или вынести добавленное в вывод. Снять предупреждение можно через `confirm` с причиной.
3. Jev подключать вторым судьёй на том же наборе, если появится ключ. Набор и скрипт для сравнения уже есть.

Цена для проекта: около 100 секунд и несколько центов на сотню фактов.

## Снимки и PDF, замер 15 ноября

В прогоне руководителя 25 фактов из 64 взяты со снимков отзывов и из PDF с условиями услуги. Текстовой копии у них нет, скрипт не сверяет даже цитату. Проверили, справится ли судья, если открыть ему сам файл.

- Настоящие факты: все 25 таких фактов из `projects/radar-1112`. 9 из PDF на три страницы, 16 с пяти снимков экрана. Разработчик сверил каждый с файлом глазами: все верны, три на границе (в утверждении есть лёгкое толкование).
- Искажённые: 21 пара в `docs/judge/distorted-img.json`. В 14 цитата настоящая, утверждение изменено: другая дата или оценка отзыва, другое число, другой период, смысл перевёрнут, один отзыв подан как массовый, совет подан как сделанное, обязанность приписана другой стороне. В 7 изменена или выдумана сама цитата: другое число, другое слово, отзыва нет на снимке.
- Судья: субагент `judge` на Haiku, инструмент только Read. Пакет на каждый файл, пары вперемешку под номерами. Вместо окружения в паре путь к файлу. Правило: сначала найти цитату в файле, потом проверить утверждение по цитате и тому, что видно рядом.

| | Результат |
|---|---|
| Искажённые, 21: ответ «нет» | 20 |
| Искажённые: ответ «частично» | 1 |
| Искажённые: пропущено | 0 |
| Настоящие, 25: ответ «да» | 25 |
| Настоящие: задето | 0 |
| Время | шесть пакетов параллельно, от 17 до 24 секунд каждый |
| Расход | около 124 тысяч токенов Haiku на 46 пар |

Все 7 подмен цитаты судья назвал «цитаты нет в источнике» и в пяти случаях написал, что стоит на её месте. Дату и число звёзд отзыва он читал со снимка верно. Единственное «частично»: к верному утверждению дописана цена, которой в документе нет.

Что нашлось попутно:
- В двух причинах судья назвал автора отзыва по имени. В инструкцию добавлено правило: имена и ники в причину не переносить.
- Два ответа из шести пришли с текстом вокруг JSON. `sa.py judge` берёт массив из ответа, лишний текст ему не мешает.

Ограничения: 46 пар, шесть файлов, один проект. Снимки чистые и крупные, PDF с текстовым слоем. На мелком шрифте, длинной ленте или скане результат может быть хуже. Искажения писал разработчик.

Решение: встроено 15 ноября. Пары со снимка или из PDF идут судье с путём к файлу, отдельным пакетом на файл. После «да» предупреждение `check` о несверенной цитате снимается. Экраны с разметкой и выводы расчётов судье по-прежнему не даём.

Проверка встроенного пути на том же проекте: `sa.py judge` собрал шесть пакетов по файлам, судья по инструкции из репозитория ответил «да» на все 25 фактов, предупреждений `check` стало 2 вместо 27. Остались замечание судьи к факту о рейтинге конкурента и превышение бюджета.

Первый запуск этой проверки дал пять ложных «частично»: сессия держала инструкцию судьи, загруженную до правки, и два судьи из шести файл не открыли. Вывод для работы: правка в `.claude/agents/` действует с нового чата. Когда судья не видит файл, он отвечает «частично», а не «да»: ошибается в безопасную сторону.

Повторить: `python -X utf8 docs/judge/img_set.py build`, затем `judge` на каждый пакет `img-S-n.json` с дополнением про поле `file`, ответы сохранить в файлы и передать в `python -X utf8 docs/judge/img_set.py score <файлы>`.

Два из них ложные: номер статьи и название компании стояли в названии источника, а судья видел только цитату и её окружение. Оговорки:
- Из 17 срабатываний в двух замерах совпали 12. Судья на Haiku не повторяется от запуска к запуску. На 62 фактах репетиции два запуска дали по 3 спорных, совпал один.
- Субагент `judge` не загружался в CLI Claude Code 2.1.319 из-за двоеточия в описании. Без него роль судьи взяла основная сессия на Sonnet и ответила «да» на все 62 факта. Автор утверждений проверяет себя мягче, чем отдельный судья.

## Как повторить

Нужны папки проектов в `projects/` и Claude Code в PATH. Из корня репозитория:

```bash
python -X utf8 docs/judge/build_set.py
```

```bash
python -X utf8 docs/judge/run_judge.py haiku ctx
```

Без `ctx` судья видит только цитату. Слово `src` после `ctx` добавляет название источника. Файлы `facts.json` и `results-*.json` в репозиторий не кладём: в них куски чужих страниц.
