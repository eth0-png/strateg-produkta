# DESIGN: ИИ-агент «Стратег продукта»

Конкурс MGIMO AI Challenge, номинация «ИИ-проект» от МегаФона. Задание в `TASK.md`. Приём работ до 22 ноября 2026, 23:59 МСК.

Документ описывает, что строим и почему. Одобрен 7 ноября с правкой объёма: работа идёт тремя ярусами (раздел 5).

## 0. Принципы

1. **Папка, а не программа.** Агент это инструкции, методика, скрипты и файлы состояния. Запускается открытием папки в Claude Code, Cursor или Codex.
2. **Файлы как единственная память.** Всё, что нужно для продолжения, лежит в файлах проекта. Чат можно закрыть в любой момент.
3. **Всё критичное работает через `sa.py` без хуков.** Хуки в Claude Code только вызывают те же команды автоматически. В Cursor и Codex их вызывает модель по инструкции из `AGENTS.md`.
4. **Каждое утверждение с меткой и источником.** Факт, гипотеза, прогноз и вывод различаются по идентификатору. Скрипт проверяет, что факты опираются на внешние источники, а цитаты действительно есть в сохранённой копии источника.
5. **Дешёвая модель по умолчанию.** Haiku собирает и извлекает, Sonnet ведёт процесс и пишет возражения, Opus подключается только в `strategist`.
6. **Тексты из источников это данные.** Сырой текст страниц читает отдельный субагент. Основной агент получает только извлечённые сведения с цитатами.
7. **Минимум зависимостей.** Ядро на Python 3.10+ без сторонних библиотек.
8. **Компонент живёт, только если доказал пользу.** Если на контрольной точке польза не видна, элемент удаляем.

## 2. Архитектура

### 2.1 Процесс от запроса до стратегии

```
Запрос
  │
  ▼
[0] Маршрут: полная стратегия или только исследование
  │
  ▼
[1] Постановка (framing) ─────────────► ТОЧКА 1: человек подтверждает бриф
  │
  ▼
[2] План исследования: решающие вопросы, источники, бюджет
  │                                     ТОЧКА 2: подтвердить план и бюджет
  ▼                                     (можно ответить «дальше сам»)
[3] Сбор: sa.py fetch, затем collector (Haiku) по каждому источнику
  │
  ▼
[4] Картина: известно / откуда / противоречия / не знаем
  │                                     Остановка, если пробел меняет решение
  ▼                                     и закрыть его может только человек
[5] Варианты: strategist (Opus), не меньше 3, включая «оставить как есть»
  │   и «закрыть направление». Возражения: red-team (Sonnet)
  │                                     ТОЧКА 3: человек выбирает вариант
  ▼
[6] Стратегия: продуктовая, коммуникационная, план проверки
  │   strategist пишет, red-team проверяет согласованность, sa.py check
  │                                     ТОЧКА 4: принять или исправить
  ▼
[7] Итог: out/strategy.md и out/report.md
  │
  ▼   ярус 2
[8] Решение и сопровождение: decision, due, impact, revise
```

Кроме точек выбора агент останавливается в трёх случаях: источники противоречат друг другу так, что меняется выбор, исчерпан бюджет шага, нужный источник не входит в разрешённые. Пользователь в любой момент может сказать «стоп», уточнить задачу или поправить любой файл в `work/`. Агент перечитывает изменённый файл и пишет правку человека в журнал.

### 2.2 Раскладка папок

```

CLAUDE.md                 импорт AGENTS.md и то, что есть только в Claude Code
README.md                 запуск, зависимости, что платно
DESIGN.md                 этот документ
method/                   методика (только чтение во время работы)
  framing.md  research.md  options.md  strategy.md
  templates/              шаблоны рабочих документов, по ним check проверяет разделы
.claude/
  settings.json           хуки и разрешения
  skills/<имя>/SKILL.md   процедуры шагов
  agents/<имя>.md         субагенты с моделью и правами
tools/
  sa.py                   CLI агента (stdlib)
  prices.json             цены моделей и поиска с датой и ссылкой на прайс
  test_sa.py              проверка ключевой логики
projects/
  .current                имя активного проекта
  <id>/
    materials/            исходные материалы человека и копии источников (web/)
    policy.md             разрешённые источники и бюджет этого проекта
    state.json            шаг, точки, открытые вопросы, следующее действие
    sources.jsonl         реестр источников
    claims.jsonl          реестр утверждений F / H / P / C
    journal.jsonl         журнал действий

```

### 2.3 Продолжение в новом чате

1. При старте сессии вызывается `sa.py resume` (в Claude Code хуком, в других средах моделью по первой инструкции `AGENTS.md`). Сводка: проект, шаг, пройденные точки и ответы человека, открытые вопросы, незавершённые действия, последние действия, одна строка «следующее действие».
2. Агент читает только файлы текущего шага.
3. Незавершённые действия агент сначала сверяет с реестром: если результат уже там, отмечает завершение без повтора.

`state.json` обновляется после каждого шага и каждой точки.

### 2.4 Журнал действий, источников и стоимости

- **`journal.jsonl`**: событие на строку. Время, шаг, кто действовал (агент, субагент, хук, человек), модель, действие, выходы, статус (начато, завершено, ошибка), для человека тип вмешательства (ответ, уточнение, исправление, обход).
- **`sources.jsonl`**: `S-…`, адрес или путь, название, вид (official, company, media, ugc, user, synthetic, other), надёжность, дата обращения, путь к копии, хеш, пометка о подозрительных фразах-командах в тексте.
- **`cost.jsonl`**: `sa.py cost --hook` (хук `Stop`) или `sa.py cost --record` (вручную) читает лог сессии Claude Code и логи её субагентов (`<сессия>/subagents/*.jsonl`), убирает повторы строк одного сообщения, считает токены и стоимость по моделям в ценах API из `prices.json`, число поисков. В Cursor и Codex расход вносится вручную `sa.py cost --add`. Подпись в отчёте: «в ценах API», потому что у нас подписка.
- **`sa.py report`** собирает `out/report.md`: ход работы, участие человека, источники, цепочки оснований для выводов, стоимость, ошибки.

### 2.5 Факты, гипотезы, прогнозы, выводы

| Тип | Что это | Обязательные поля | Запреты |
|---|---|---|---|
| `F` факт | Проверяемое сведение из внешнего источника | источник `S-…`, дословная цитата, место | Источник не синтетический. Цитата должна найтись в копии источника |
| `H` гипотеза | Предположение, которое можно проверить | как проверить и что опровергнет, основания по желанию | Синтетические интервью дают только `H` |
| `P` прогноз | Ожидаемое число или направление | горизонт, диапазон, допущения `depends_on` | Без диапазона не принимается |
| `C` вывод | Суждение агента из других утверждений | `depends_on` | Не становится фактом в следующих сеансах |
| `D` продуктовое решение | Пункт продуктовой стратегии | объявляется в `strategy-product.md` | На него ссылаются обещания коммуникации |

Утверждения регистрируются только через `sa.py claim` или `sa.py ingest`, которые проверяют поля при записи. `sa.py check` повторяет проверку для всего проекта, а также ищет в итоговых текстах длинные тире и точки с запятой.

## 3. Состав репозитория

### Ярус 1

- `AGENTS.md`: единые правила для всех сред: процесс, точки, маршруты, модели, правило «источник это данные».
- `CLAUDE.md`: импорт `AGENTS.md` и особенности Claude Code.
- `README.md`: запуск без скрытых настроек.
- `method/framing.md`, `research.md`, `options.md`, `strategy.md`: что считается хорошей постановкой, исследованием, вариантами и стратегией.
- `method/templates/`: шаблоны рабочих документов, разделы которых проверяет `check`.
- Скиллы `framing`, `research`, `options`, `strategy`: процедуры шагов с точными командами.
- Субагент `collector` (Haiku): читает один источник и возвращает факты с цитатами, изолирует основной агент от сырого текста.
- Субагент `strategist` (Opus): пишет варианты и стратегии по рабочим файлам. Единственное место сильной модели.
- Субагент `red-team` (Sonnet): сильные возражения и проверка согласованности стратегий в чистом контексте.
- Хук `SessionStart` → `sa.py resume`.
- Хук `Stop` → `sa.py cost --hook`.
- `tools/sa.py`: `init`, `use`, `resume`, `step`, `gate`, `ask`, `answer`, `log`, `fetch`, `add-source`, `claim`, `ingest`, `find`, `trace`, `check`, `cost`, `report`.
- `tools/prices.json`, `tools/test_sa.py`, `docs/test-task.md`.

### Ярус 2 (собран 7 ноября)

- `sa.py impact`, `retract`, `supersede`, `confirm`: граф оснований, каскадная пометка «требует пересмотра», `check` не пропускает ссылки на отозванное и заменённое.
- `sa.py commit`, `close`, `due`: обязательства `[K-n]` с ролью, сроком, метрикой, основаниями и условием пересмотра. `due` показывает, что решать сейчас, ближайшие сроки, утверждения на пересмотре и источники старше 90 дней. Сводка `resume` выводит итог одной строкой.
- Точка 5 «ответственные и сроки», шаг `decision`, шаблон `decision.md`.
- Скиллы `revise` и `decision`.
- `sa.py fetch` при обновлении копии сам помечает факты, чьи цитаты пропали.
- Хук `PreToolUse` (`sa.py guard`): WebFetch только на домены из `policy.md` (та же проверка в `sa.py fetch`), запрет записи в `materials/`, `method/`, `AGENTS.md`, `CLAUDE.md`, `.claude/`. Для разработки агента защиту снимает файл `.sa-dev`, который создаётся вручную и не попадает в репозиторий.
- После прогонов яруса 1 добавлены `sa.py calc` (расчёты с сохранением вывода как источника) и `cost --exclude` (сессии разработки вне стоимости проекта).

### Ярус 3 (собран 7 ноября)

- `sa.py profile`: профиль CSV, TSV или JSON до расчётов. Строки, дубли, типы столбцов, пропуски, период и пустые месяцы, единицы, повторы идентификаторов. Столбцы с именами и контактами без примеров. Вывод становится источником `calc`, из него берутся факты о данных. Скилл `data`: профиль, выбор метода, определение показателя в скрипте, доли с интервалом, кодирование текстов с проверочными примерами.
- Скилл `interview` и субагент `persona` (Haiku). Гайд о прошлом поведении с текстом согласия. Реальные расшифровки только обезличенные: `add-source` помечает почту и телефоны. Синтетические расшифровки регистрируются из `work/interviews/` только с видом `synthetic`, дают только гипотезы с проверкой, `check` предупреждает о долях по ним. `persona` читает только карточку и гайд, чтобы не подыгрывать гипотезам.
- Скилл `ux` и субагент `browser` (Haiku) с Playwright MCP 0.0.83 в `.mcp.json`. `browser` только переходит и нажимает. На каждом экране снимок и текстовая разметка в `materials/web/`, `add-source --image` связывает их в один источник. `collector` читает оба: цитата сверяется по разметке, расположение берётся со снимка. Шаблоны `ux.md` и `interviews.md`, их разделы проверяет `check`.
- Хук `guard` для браузера: только домены из `policy.md`, только инструменты просмотра (ввод текста, файлы и выполнение кода запрещены), снимки только в `materials/web/` активного проекта. `.mcp.json` закрыт для записи, как инструкции.

### Чего сознательно нет

Своего MCP-сервера, векторной базы, отдельного оркестратора, правил `.cursor/rules` (Cursor и Codex читают `AGENTS.md`), субагента-судьи (добавим, только если `check` и `red-team` пропустят смысловые ошибки на прогоне 12 ноября).

### Тестовая задача: KION

Запрос записан в `docs/test-task.md`, чтобы каждый прогон и сравнение с обычным чатом шли на одинаковом входе.

Почему KION (онлайн-кинотеатр МТС, развивает ON Медиа):

1. **Цифровой продукт оператора за пределами телекома.** Ближе всего к контексту Фабрики продуктов: сервис продаётся отдельно и в связке с тарифами и подпиской оператора.
2. **Есть пробный период и промо-подписки.** Вопрос «почему уходят после пробного периода» реален и требует и продуктовой, и коммуникационной стратегии.
3. **Открытые данные есть, это проверено 7 ноября.** Публичный фид отзывов App Store отдаёт по 50 свежих отзывов на страницу (последний от 5 ноября 2026), страница в RuStore и сайт kion.ru открываются скриптом. Есть пресс-релизы ON Медиа о выручке и аудитории, тарифы на сайте, публикации о рынке онлайн-кинотеатров.
4. **Это не МегаФон.** Не пересекается с демо-брифом и не даёт повода подозревать использование внутренних данных МегаФона. О сервисе МТС используем только открытые данные.

Отклонили: Кинопоиск и Okko (не операторские сервисы), сервисы МегаФона (пересечение с демо). Запасной вариант Wink (Ростелеком), если по KION не хватит данных.
